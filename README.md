# Binance AI Paper Trading Bot — مشروع تجريبي

**الحالة:** إصدار أولي وظيفي للتداول الورقي الفوري Spot، وتحليل بيانات Spot وUSDⓈ-M Futures، وليس نظام تداول حقيقي جاهز للإنتاج.

## ما يعمل فعليًا
- FastAPI مع توثيق `/docs`، وحماية نقاط التحكم برمز `X-API-Token`.
- أسعار الشموع من واجهات Binance العامة، وحساب EMA(12/26) وRSI(14) وATR(14) باستخدام الشموع المغلقة فقط.
- عامل خلفية يراجع السوق كل 30 ثانية، ويتخذ قرارات BUY وSELL وفق استراتيجية بسيطة قابلة للاختبار.
- محفظة Spot تجريبية برصيد ابتدائي 10,000 USDT، وقف خسارة، هدف ربح، رسوم وانزلاق تقديري، حد للصفقات اليومية وحد للخسارة المحققة.
- قاعدة بيانات PostgreSQL مع Docker Compose، أو SQLite للتشغيل المباشر.
- مساعد شرح بالعربية باستخدام OpenAI API عند الطلب، وليس منفذ أوامر.
- تطبيق Android Studio بواجهة Compose لبدء/إيقاف المحاكاة والتحليل ومراجعة السجلات.

## حدود أمان مهمة
- **لا يوجد أي كود لإنشاء أوامر Binance حقيقية أو استخدام مفاتيح تداول Binance.** التداول الحقيقي معطل بالكامل، وليس مجرد زر يمكن تشغيله.
- Futures مدعوم لجلب البيانات والتحليل فقط. محاكاة العقود الآجلة وتنفيذها غير منفذين بعد.
- وقف الخسارة محاكاة تعتمد على التحديث الدوري؛ ليست أمر وقف خسارة موضوعًا في البورصة، وقد تتجاوز الأسعار نقطة الوقف بين تحديثين.
- حساب المحفظة لا يحجز رأس المال النقدي الفعلي، بل يحاكي صفقة واحدة Spot في كل مرة. لا تدعم النسخة مراكز متعددة أو صفقات بيع على المكشوف.
- الحد اليومي للخسارة يعتمد على الخسارة **المحققة** وليس التراجع اللحظي؛ لا يُعتمد عليه لإدارة أموال حقيقية.
- لا تضمن الاستراتيجية الربح؛ يجب إجراء اختبارات تاريخية وورقية مطولة قبل التفكير بالتداول الحقيقي.

## تشغيل محلي على Windows (بدون Docker)
1. ثبّت Python 3.12.
2. افتح PowerShell في `backend`:
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   $env:APP_API_TOKEN="choose-a-long-random-token"
   $env:OPENAI_API_KEY="your-openai-key" # اختياري
   uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
3. افتح `http://localhost:8000/health` ثم `http://localhost:8000/docs`.
4. في Swagger، اضغط Authorize وأدخل رمز الاتصال في `X-API-Token` (أو أرسل الترويسة يدويًا).
5. اختر POST `/settings`، ثم POST `/start`، وراقب GET `/status` وGET `/trades`.
6. سيستخدم SQLite محليًا تلقائيًا. قد تمنع قيود شبكة أو منطقة استخدام واجهة Binance؛ عندئذ سيظهر خطأ ولن تنفذ المحاكاة صفقات جديدة.

## تشغيل Docker + PostgreSQL
1. ثبّت Docker Desktop.
2. انسخ `.env.example` إلى `.env`، وعدّل `POSTGRES_PASSWORD` و`APP_API_TOKEN` إلى قيم قوية؛ ضع مفتاح OpenAI اختياريًا.
3. نفذ من جذر المشروع:
   ```bash
   docker compose up --build -d
   docker compose logs -f api
   ```
4. API على `http://127.0.0.1:8000` من الكمبيوتر فقط.
5. لا ترفع ملف `.env` إلى Git أو ترسله لأحد.

## Android Studio
1. افتح مجلد `android` باستخدام Android Studio، واتركه يزامن Gradle. يتطلب JDK 17 وAndroid SDK 35.
2. في المحاكي، يستخدم التطبيق `http://10.0.2.2:8000` للوصول إلى الخادم المحلي.
3. أدخل `APP_API_TOKEN` داخل شاشة التطبيق، ثم اختبر التحديث والتشغيل. **لا تستخدم رمز خادم حقيقي عالي الصلاحية في نسخة منشورة**؛ هذه مصادقة تجريبية فقط.
4. على هاتف حقيقي، يجب تغيير عنوان الخادم إلى عنوان قابل للوصول من الهاتف. لا تعرض API للعامة عبر HTTP؛ استخدم HTTPS ومصادقة مستخدمين حقيقية في النشر.
5. لا يتضمن الأرشيف Gradle Wrapper binaries؛ افتح المشروع عبر Android Studio المثبت لديه Gradle، وقد تحتاج إلى توليد wrapper محليًا.

## الاختبارات
```bash
cd backend
python -m pytest -q
```
الاختبارات تشمل حساب المؤشرات وفتح وإغلاق صفقة ورقية اصطناعية. لا توجد اختبارات تكامل حية مع Binance في هذه النسخة.

## أمثلة API
```bash
curl -H "X-API-Token: YOUR_TOKEN" http://localhost:8000/status
curl -X POST -H "X-API-Token: YOUR_TOKEN" -H "Content-Type: application/json" -d '{"market":"spot","symbol":"BTCUSDT","timeframe":"1m"}' http://localhost:8000/analyze
curl -X POST -H "X-API-Token: YOUR_TOKEN" http://localhost:8000/start
```

## خطة النقل من المحلي إلى VPS
1. اختبر محليًا عدة أسابيع، وراقب انقطاع الاتصال والأخطاء والرسوم.
2. استخدم خادم Linux مع Docker، واحتفظ بـ PostgreSQL على شبكة داخلية.
3. ضع API خلف HTTPS reverse proxy مع هوية مستخدم حقيقية، وصلاحيات محددة، ومحدد طلبات.
4. أضف تنبيهات، نسخًا احتياطيًا مشفرًا، اختبارات تكامل، مراقبة تعطل الخدمة، وإدارة أسرار.
5. أضف اختبارًا تاريخيًا يتجنب تسرب بيانات المستقبل ويحسب التمويل والتصفية قبل تطوير محاكاة Futures.
6. لا تضف تداولًا حقيقيًا إلا بعد اختبار مستقل لسلامة الأوامر والتوافق مع قواعد Binance والأنظمة المحلية.

تطبيق إنتاجي منشور، إدارة مستخدمين، إشعارات فورية، backtesting متقدم، websocket، محاكاة Futures، أو تداول حقيقي. يجب تطويرها واختبارها في مراحل لاحقة.
